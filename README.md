# 👻 Бюро переселения привидений

Тестовое задание **AI-first Developer 2.0** для MOX. Веб-приложение для оператора
бюро, которое переселяет привидений из старых домов в новые места обитания:
подбирает подходящее место, объясняет решение, показывает, если переселение
невозможно, и позволяет вручную скорректировать выбор с предупреждением о
конфликтах.

- 🔗 Рабочее приложение: https://mox-ghost-relocation-bureau.vercel.app
- 🔗 Репозиторий: https://github.com/aby1ovva/mox-ghost-relocation-bureau
- Вкладка **AI Worklog** встроена прямо в интерфейс приложения (третья вкладка).

## Быстрый старт

Требуется Node.js 20+ и npm.

```bash
npm install
npm run dev       # http://localhost:5173
```

Другие команды:

```bash
npm run test      # юнит-тесты (Vitest)
npm run build     # прод-сборка + проверка типов
npm run preview   # локальный просмотр собранного билда
```

Секретов и токенов в проекте нет — приложение полностью фронтенд-локальное,
данные хранятся в `localStorage` браузера.

## Как устроено приложение

Три вкладки:

1. **Диспетчерская** — список заявок от привидений и мест переселения,
   автоматический подбор с объяснением, ручной override с предупреждением о
   нарушениях, формы добавления новых заявок/мест, кнопки сброса к примеру
   данных и полной очистки (для демонстрации пустого состояния).
2. **Отчёт** — сколько привидений расселено, сколько без места, какие заявки
   самые проблемные (без места; ручное размещение нарушает условия; либо
   расселена благополучно, но альтернативы нет — при малейшем изменении может
   потерять место), какие места перегружены.
3. **AI Worklog** — честный отчёт о процессе разработки с помощью AI.

### Модель данных

**Заявка привидения**: имя, уровень тревожности (1–5), любимая температура,
дедлайн переселения, особые условия (нужен чердак / боится зеркал / нельзя
рядом с людьми / любит сырость / нужна тишина / не переносит яркий свет).

**Место переселения**: название, вместимость, температура, освещение, уровень
шума, влажность, наличие людей/зеркал/чердака.

### Алгоритм подбора

Сначала отсекаются места, которые физически не подходят (жёсткие ограничения):

- дедлайн уже прошёл → переселение невозможно вообще, независимо от места;
- место уже заполнено;
- нужен чердак, а его нет;
- призрак боится зеркал, а в месте есть зеркала;
- нельзя селить с людьми, а в месте есть люди.

Среди оставшихся кандидатов побеждает тот, что лучше по мягкому скорингу:
близость температуры, совпадение по влажности/шуму/освещению под особые
условия, и штраф за шум/людей пропорционально уровню тревожности призрака.
Полная реализация — `src/logic/matching.ts` (покрыта unit-тестами).

Ручной выбор места пользователем **не блокируется**, но если он нарушает
жёсткие ограничения, приложение явно показывает предупреждение с перечнем
нарушений (`evaluateManualChoice`).

## Тесты

15 unit-тестов на алгоритм подбора и построение отчёта:

```bash
npm run test
```

Плюс — ручные сценарии проверки ниже (задание требует минимум 3 теста ИЛИ 5
подробных ручных сценариев; здесь есть и то, и другое).

## Чеклист ручной проверки (пройден перед сдачей)

1. **Пустой список заявок.** Нажать «Очистить всё» на вкладке «Диспетчерская» →
   список заявок и список мест показывают пустое состояние с понятным текстом,
   вкладка «Отчёт» показывает «Заявок пока нет».
2. **Заявка без подходящего места.** В примере данных «Забытый Профессор» имеет
   дедлайн в прошлом → карточка показывает ❌ и причину «дедлайн переселения
   уже прошёл», заявка попадает в «Проблемные заявки» отчёта.
3. **Место переполнено.** В примере данных «Старый маяк» (вместимость 2)
   заполняется двумя заявками → карточка места получает оранжевую рамку и
   счётчик «2/2», место попадает в «Перегруженные места» отчёта.
4. **Ручной выбор конфликтует с условиями.** Для заявки с условием «нельзя
   рядом с людьми» вручную выбрать место, где есть люди (например,
   «Библиотека») → появляется жёлтое предупреждение с точным перечнем
   нарушенных условий, выбор при этом не блокируется.
5. **Понятная ошибка ввода.** В форме «Новая заявка» нажать «Добавить заявку»
   с пустым именем → форма показывает «Укажите имя привидения» и не создаёт
   заявку; аналогично для некорректной даты/температуры. Дополнительно
   верхнеуровневый `ErrorBoundary` перехватывает неожиданные ошибки рендера и
   показывает понятный экран вместо белого экрана.

Все пять сценариев пройдены вручную в браузере перед сдачей (см. AI Worklog).

## Технические ограничения (честно)

- Данные хранятся только в `localStorage` браузера — нет бэкенда и
  многопользовательского доступа (см. AI Worklog → «Что доработать»).
- Веса алгоритма подбора захардкожены в `src/logic/matching.ts`.
